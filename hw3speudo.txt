computePrefixAutomation(P)
    m = |P|
    pi = computePrefixFunction(P)
    A = 2D array with (m + 1) × |Σ| entries
    for q = 0 to m
        for c in Σ
            if q == 0 and P[q + 1] != c
                A[q][idx(c)] = 0
            else if q == m or P[q + 1] != c
                A[q][idx(c)] = A[pi[q]][idx(c)]
            else
                A[q][idx(c)] = q + 1
    return A
The idea of the algorithm as the following: given that the previous q characters are matched, if the next character is c, how long will the prefix-suffix pair be at this moment. So A[q][idx(c)] = q + 1 if there's a match. Otherwise, we fall back onto pi[q] and how it handles character c when q = pi[q]. 
Time complexity: The the inner loop take O(|Σ|) time to iterate through every character in the set, and the outer loop take will run m iterations, the overall time complexity is O(m|Σ|).
Space complexity: the bottleneck of space complexity is the 2D array, which sizes (m + 1) * |Σ|, so the space complexity is O(m|Σ|)

repetitiveStringMatching(T, P, c)
    n = |T|
    m = |P|
    pi = Compute-Prefix-Function(P)
    A = computePrefixAutomation(P)
    f[0:m−1] = new array
    g[0:m−1] = new array
    for j = 0 to m - 1
        q = j
        cnt = 0
        for i = 1 to n
            q = A[q][idx(T[i])]
            if q == m
                cnt++
                q = pi[q]
        f[j] = q
        g[j] = cnt
    q = 0
    cnt = 0
    for i = 1 to c
        cnt = cnt + g[q]
        q = f[q]
    return cnt

We can pre-compute the resulting q given the current number of matched characters and the next input character. By doing so, when deriving the values of f and g arrays, we can find the next state q in O(1) time, avoiding the while loop.
Time complexity: as elaborated in the previous question, deriving the computePrefixAutomation function takes O(m|Σ|) time. Because accessing the values in A take O(1) time, the total time spend in the double for loop takes O(mn) time. and the final for loop takes O(c) time, resulting in an overall time complexity of O(m|Σ| + mn + c).
Space complexity: the computePrefixAutomation function creates a 2D array with (m + 1) × |Σ| entries, so the space complexity is O(m|Σ|). Array f and g takes O(m) space, so the overall space complexity is O(m|Σ|)

anagramMatching(T, P)
    m = P.length
    n = T.length
    B = m + 1
    MOD_NUM = pow(10, 16) + 61
    hashValueP = hashValueT = 0
    cnt = 0
    for i from 1 to m
        hashValueP = (hashValueP + B ^ getValue(P[i]) % MOD_NUM) % MOD_NUM
        hashValueT = (hashValueT + B ^ getValue(T[i]) % MOD_NUM) % MOD_NUM
    if hashValueP == hashValueT
        cnt++
    for i from m + 1 to n
        prevCharVal = B ^ getValue(T[i - m]) % MOD_NUM
        newCharVal = B ^ getValue(T[i]) % MOD_NUM
        hashValueT = (hashValueT + newCharVal - prevCharVal + MOD_NUM) % MOD_NUM
        if hashValueP == hashValueT
            cnt++
    return cnt

The hash function is H(S) = ∑ count(c) * B ^ getValue(c), and B = m + 1 is a number greater than the length of P, preventing any character from carrying over into the next base position. By doing so, the order of the characters does not matter, and different string will produce different hash values. The rest of the logic is the same as the Rabin-Karp algorithm.
Time complexity: since the calculating x ^ y takes O(logy) time, calculating the exponential for one hashValue takes O(log|∑|) time, for the exponent depends on the size of the set. We will calculate one hash value for every character in T and P, resulting in a O((m + n)log|∑|) time complexity
Space complexity: since we derive the hash value by rolling through the strings, every operation in the algorithm takes O(1) space, resulting in O(1) overall space complexity.

prefixSuffix(S)
    n = |S|
    pi = createArray(size = n)
    pi[1] = 0
    validLen = createArray(size = n, all elements initialized to 0)
    freq = createArray(size = n, all elements initialized to 1)
    k = 0
    for q = 2 to n
        while k > 0 and S[k + 1] != S[q]
            k = pi[k]
        if S[k + 1] == S[q]
            k = k + 1
        pi[q] = k
    for i = n downto 1
        if pi[i] != 0
        freq[pi[i]] += freq[i]
    q = n
    i = 0
    while q != 0
        validLen[i++] = q
        q = pi[q]

    cnt = 0
    for i = 1 to n
        if validLen[i] == 0
            return cnt
        cnt = cnt + freq[validLen[i]]
    return cnt

We create a validLen array to store the length of the subarray that meets the requirement, and a freq array with freq[i] storing the total appearances of S[1:i] in the array. Since every subarray will appear at least once, we initialize every element to 1. Since S[1:pi[q]] is the longest subarray in S[1:q], we utilize this trait to find every value in the freq array. Then we recursively call the pi values to find out all substrings that meet the requirement of being a prefix and suffix, and we sum up the total appearances of these substrings.
Time complexity: the prefix computation process takes O(n) time, as proved in the lecture. Dealing with the freq array with the for loop take O(n) time. Dealing with the validLen array with the while loop takes O(n) time since it looks at every element in the string at most once. The last for loop that calculates the final count with the for loop takes O(n) times as well. Overall, the time complexity is O(n)
Space complexity: we created three arrays: pi, validLen, freq, all of which are O(n) size every other variables take O(1) space, resulting in an overall space complexity of O(n).

PartialInversePair(array A, x, k)
    n = A.length
    cnt = 0
    ptrfront = 1
    ptrback = x + 1
    while ptrfront <= x and ptrback <= n
        if A[ptrfront] > k * A[ptrback]
            cnt += x - ptrfront + 1
            ptrback++
        else
            ptrfront++
    return cnt

Since the two subarrays is sorted non decreasingly, if (i, j) is a partial inverse pair(PIP), (i + 1, j), (i + 2, j)...(x, j) will also be PIPs, so when if A[i] > k * A[j] holds, we can move to the next element of subarray A[x + 1:n]. If A[i] > k * A[j] does not hold, (i, j + 1), (i, j + 2)...(i, n) will not be PIPs, so we can move on to the next element of the subarray A[1:x].
Complexity: we scan through each element in array A only once, resulting in a O(n) time and O(1) space since we only use constant number of variables.

PartialInversePair(array A, low, mid, high, t)
    cnt = 0
    ptrfront = low
    ptrback = mid + 1
    while ptrfront <= mid and ptrback <= high
        if A[ptrfront] > t * A[ptrback]
            cnt += mid - ptrfront + 1
            ptrback++
        else
            ptrfront++
    return cnt

merge(B, low, mid, high)
    newSizeB = high - low  + 1
    k = 1
    i = low
    j = mid + 1
    newB = createArray(size = newSizeB)
    while i <= mid and j <= high
        if B[i] <= B[j]
            newB[k++] = B[i++]
        else 
            newB[k++] = B[j++]
    while i <= mid
        newB[k++] = B[i++]
    while j <= high
        newB[k++] = B[j++]
    for i from 1 to newSizeB
        B[low + i - 1] = newB[i]

SuperInversePair(array B, low, high, t)
    if low >= high
        return 0
    mid = (low + high) / 2
    leftCount = SuperInversePair(B, low, mid, t)
    rightCount = SuperInversePair(B, mid + 1, high, t)
    crossCount = PartialInversePair(B, low, mid, high, t)
    merge(B, low, mid, high)
    return leftCount + rightCount + crossCount

To use the PartialInversePair function, we need two sorted halves. We adapt Merge Sort to achieve this in O(mlogm) time. Because standard merging only compares strict values (B[i] <= B[j]), we must decouple the pair-counting logic from the sorting process.We recursively call SuperInversePair to divide the array, then use PartialInversePair to count the valid pairs across the two halves before they are merged. Doing this step before merging ensures the pairs we find still meet the original positional condition of i < j. The total count is simply the sum of all pairs found at every recursive layer.
Time complexity: At each recursive layers, both the PartialInversePair and the merge function require takes O(m) time. All other operations take O(1) time. The total number of layers is logm, resulting in a total time complexity of O(mlogm).
Space complexity: the total space malloc-ed by the merge function throughout the process is m + m/2 + m/4 + ... = O(2m)  = O(m), and the total logm stack calls take up O(logm) spaces, resulting in O(m) + O(logm) space, satifiying the O(mlogm) constraint

compare(s1, s2)
    len = min(|s1|, |s2|)
    for i = 1 to len
        if s1[i] < s2[i]
            return -1
        if s1[i] > s2[i]
            return 1
    if |s1| < |s2|
        return -1
    else if |s1| > |s2|
        return 1
    else return 0

mergeSort(A, low, high)
    if low >= high
        return
    mid = (low + high) / 2
    mergeSort(A, low, mid)
    mergeSort(A, mid + 1, high)
    newSize = high - low + 1
    newA = createArray(size = newSize)
    leftPtr = low, rightPtr = mid + 1, k = 1
    while leftPtr <= mid and rightPtr <= high
        if compare(A[leftPtr], A[rightPtr]) <= 0
            newA[k++] = A[leftPtr++]
        else
            newA[k++] = A[rightPtr++]
    while leftPtr <= mid
        newA[k++] = A[leftPtr++]
    while rightPtr <= high
        newA[k++] = A[rightPtr++]
    for i = 1 to newSize
        A[low + i - 1] = newA[i]

    return A

Assume the set A contains pointers to each string. We simply apply merge sort on A, and do the comparison character by character.
Time complexity: The merge sort recursion tree has O(log n) layers. As for the comparison, a single comparison takes O(min(|s1|, |s2|)), and a string will only be added to the newA once per layer. Therefore, on each layer, the time spent on scanning the string will be O(S1 + S2 + ... + Sn) = O(m). Therefore, the overall time complexity will be O(m * logn)
Space complexity: Since there are m characters in total, storing the characters takes O(m) space. The original pointer array take O(n) space. During each merging process we will have to create an extra O(n) space, but it will be freed after each iteration, so the space it take is O(n). The stack call takes O(logn) space. Hence, the overall space complexity is O(m + n + n + logn) = O(m + n)

PMaximizer(array T, k)
    n = |T|
    mergeSort(T, by = speed, order = descending)
    scoreSum = 0
    heap = createArray(size = k)
    for i from 1 to k
        heap[i] = T[i]
        scoreSum += T[i].score
    P = scoreSum * T[k].speed
    minHeapify(heap, 1, k)
    for i from k + 1 to n
        if T[i].score > peek(heap)
            scoreSum = scoreSum + T[i].score - pop(heap)
            insert(heap, T[i], 1, k)
            newP = scoreSum * T[i].speed
            if newP > P
                P = newP
    return P

Since the multiplier is the minimum speed, we first sort T by speed in descending order. Then we create a min-heap to dynamically include the highest scores we see so far and take the minimum speed into consideration to derive the best score and combination so far.
Time complexity: the merge sort take O(nlogn) time. The first for loop takes O(k) time to store the first k data. The second for loop runs for n - k iterations, while the insert process takes O(logk) time, so this for loop costs O((n - k) * logk) time. Overall, the time complexity is O(nlogn + k + (n - k) * logk) = O(nlogn).
Space complexity: the array "heap" takes O(k) = O(n) space. Other than that, other variables take O(1) space. The overall space complexity meets the O(n) requirement.
